# ART_PIPELINE — как приносить SVG-арт в игру

Процесс: **владелец генерит SVG во внешнем ИИ → агент чистит, размечает,
анимирует и встраивает**. Гайд фиксирует технические требования, чтобы
сгенерённый файл не испортил игру (перформанс мобильного вебвью) и лёг в
пайплайн без переделки. Написан по итогам босс-реворка 2.0 (июль 2026) —
эталоны конвенций: `#boss-orca-giant` и `#boss-shark-side` в index.html.

## Когда это нужно

Любой новый игровой арт: боссы, препятствия новых биомов, декор фона,
питомцы, скины. Если проще описать словами — можно по-прежнему просто
описать, агент нарисует сам; этот файл — для случая «я сгенерил красивое,
вставь в игру».

## Жёсткие требования к файлу

Нарушение любого пункта = агент сначала чинит файл, потом встраивает.
Пункты с ⚠ агент не чинит, а просит перегенерить — они ломают игру.

1. **Чистый inline-SVG**: только теги `svg`, `g`, `path`, `circle`,
   `ellipse`, `rect`, `line`. Без `<image>`/растра/base64 (⚠ — раздувает
   страницу и мылится), без `<style>`/`<script>`/`<text>`/`<font>`
   (стили — только атрибутами `fill`/`stroke`).
2. **Прямоугольный viewBox с небольшим запасом** вокруг силуэта
   (например `0 0 340 460`), пропорции viewBox = пропорции будущего
   CSS-бокса (иначе letterbox-поля).
3. **Без SVG-фильтров** (`<filter>`, `filter=`) — blur/shadow на больших
   площадях убивают FPS вебвью (⚠). Объём рисуем краской: контртень,
   блик, рим-лайт отдельными path.
4. **Лимит размера**: ~10 КБ и ~40 путей на персонажа. ИИ-генераторы
   любят выдавать тысячи микропутей — такое агент упрощает, но лучше
   сразу просить «flat vector, few paths».
5. **Координаты с точностью максимум 1 знак** после запятой (агент
   округлит сам, но файл будет легче сразу).
6. Один персонаж = один файл. Фон/сцену не включать.

## Обязательные группы-слои

Всё, что должно двигаться отдельно, — в именованной группе `<g>` с
классом по трафарету `XX-часть` (XX — короткий префикс ассета, у
косатки-гиганта `og-`, у акулы-профиля `ss-`):

```
XX-body        корпус (не анимируется, база)
XX-jaw-upper   верхняя челюсть
XX-jaw-lower   нижняя челюсть (обычно главная анимируемая часть)
XX-fin-dorsal  спинной плавник
XX-fin-pect-l / XX-fin-pect-r   грудные плавники
XX-tail        хвост
XX-eye         глаз (моргание/блик)
```

Не всё обязательно присутствует — но если часть есть и будет двигаться,
она обязана быть отдельной группой. Правило анимации: **только
`transform`/`opacity` на группах, `transform-origin` в px** (идиома
проекта — см. `#player .rig` и `og-jaw-lower` в css/styles.css).

## Палитра

- Разовый арт (боссы, ивент-декор): **hex прямо в атрибутах** — ок.
- Тематика биомов (то, что перекрашивается по миру/фазе суток):
  **CSS-переменные** `var(--…)` — см. `--bark-*`/`--wood-*` в
  css/styles.css. Если не уверен — hex, агент переведёт при встраивании.

## Шаблоны промптов для генерации

Подставь своё, сохрани требования из середины:

> Нарисуй чистый минималистичный SVG: белая акула в профиль, нос вправо,
> пасть распахнута, видны зубы. Плоские цвета без градиентов и фильтров,
> максимум 25 путей, viewBox="0 0 260 90". Раздельные группы с классами:
> ss-body, ss-jaw-upper, ss-jaw-lower, ss-fin-dorsal, ss-tail, ss-eye.
> Только код SVG, без пояснений.

> Нарисуй SVG-силуэт косатки в вертикальном прыжке анфас снизу,
> viewBox="0 0 340 460", пасть раскрыта к верхнему краю, белые глазные
> пятна и горло, грудные плавники расправлены в стороны. Плоские цвета,
> без фильтров и растра, до 30 путей. Группы: og-body, og-jaw-upper,
> og-jaw-lower, og-fin-pect-l, og-fin-pect-r, og-tail. Только код.

Если генератор выдаёт растр (png/jpg) — тоже можно принести: агент
перерисует векторно по референсу, это дольше, но работает.

## Процесс интеграции (делает агент)

1. Файл/код от владельца (в чат или в `assets/`).
2. Чистка: метаданные редакторов, лишняя точность, мусорные пути.
3. Чеклист требований выше; разметка недостающих групп.
4. Встраивание inline в index.html + CSS-анимации состояний.
5. **Бамп `?v=N`** у styles.css (кэш вебвью Telegram).
6. Скриншот-итерации в превью → маленький коммит → пуш → **проверка на
   реальном телефоне** владельцем.

## Грабли (кровью)

- В CSS-комментариях **никогда не писать `*/` внутри текста** (даже как
  «tele-* / strike-*» без пробелов) — правило после комментария молча
  выпадает; инцидент «невидимые боссы», июль 2026.
- Вебвью Telegram кэширует styles.css сквозь `max-age=0` — правка CSS
  без бампа `?v=N` на телефоне «не видна».
- Анимировать только transform/opacity; layout-свойства (width/top/…)
  в кадре не трогать.
- Тяжёлый drop-shadow допустим один и маленький (см. `#boss-shark svg`),
  на больших силуэтах — нельзя.
